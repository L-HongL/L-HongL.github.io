## 一个请求如何产生

### 创建请求

我们打开浏览器，输入网址 `http://www.bornhup.com` 后，浏览器就会向网站发送请求，但是不知道如何发送。于是它会通过 DNS 等办法，找到这个网址对应的 IP 地址。

浏览器使用的是什么办法，暂时不用细究。IP 地址是网络中用来标识一台设备或一个网络接口的“地址”，可以把 IP 看作门牌号，如果其他设备知道了你的门牌号，就可以把信息“寄”给你。

---

### 打包 HTTP 层

知道了 IP 地址，也就知道要往哪里发送请求了，浏览器就正式开始打包它的请求。对于浏览请求，会使用 HTTP 协议将请求内容组织起来，如果需要加密传输，HTTP 数据会经过 TLS 保护，也就是使用 HTTPS。

用 HTTP 打包好请求内容，相当于将你想寄出去的一个物品，用纸盒包裹好。接下来，要将包裹交给物流。

---

### 打包 TCP/UDP 层

物流有很多种——UDP、TCP，他们是**传输层协议**。请求会再封装一次，把请求用传输协议打包起来。

系统会根据端口号，知道发出去的数据和收到的数据应该交给哪个程序。因为一台设备上可以同时运行很多程序，例如游戏、QQ、微信等，操作系统会根据端口号将数据交给对应的程序，保证属于 QQ 的消息不会发到游戏的聊天框中。

---

### 打包 IP 层

经过两次封装后，就要给包裹贴上运输单，写上发货地和收货地，这时就要写上请求双方的**IP 地址**，也就是双方的门牌号。

---

### 打包 MAC 层

知道了门牌号，但是网络上没有一条能直接通往目的地的路，不能将请求直接发给目标。我们需要将请求交给当前网络的网关，由该网关根据目标 IP 查询路由表，决定下一步应该往哪里转发。

请求最终经过多个网关的逐跳转发，到达目标 IP 所在的网络，才能直接交给目标设备。

这就需要用**MAC 地址**再封装一次请求。MAC 地址相当于当前链路中设备的地址，包裹根据 MAC 地址转交给下一跳设备。经过下一跳后，又会重新封装新的 MAC 地址继续转交。

---

### 发送过程

好了，经过深思熟虑的打包请求，终于可以发送了。

请求会根据目标 IP 确定下一跳，然后获得下一跳设备的 MAC 地址。

当一个路由器拿到请求后，会先处理 MAC 层，确认这个数据帧是发给自己的，然后取出其中的 IP 数据包。

路由器查看目标 IP，并根据自己的路由表决定是否需要继续转发。

如果需要继续转发，就确定下一跳，并重新封装新的 MAC 地址，然后把数据发送出去。

因此，请求在经过多个路由器的过程中，**IP 地址主要保持端到端的目标，而 MAC 地址会随着每一跳不断重新封装。**

当请求最终到达目标设备后，目标设备的操作系统会继续处理 IP 层、TCP/UDP 层的数据，并根据端口号找到对应的程序，最终目标程序得到 HTTP 请求内容。
